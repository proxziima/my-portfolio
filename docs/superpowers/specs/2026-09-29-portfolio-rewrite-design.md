# Portfolio rewrite — design

Date: 2026-09-29 · Branch: `feat/portfolio-rewrite`

## 1. Goal

Rebuild the portfolio in `apps/web` from scratch. Use `docs/template-portfolio`
(and its source of truth, `reference/reel.html`) as the **UI, UX and motion
reference only**. Code is not copied. Content comes from `apps/payload`, which
is reduced from the Payload website template to a headless CMS for the
portfolio, with the MCP plugin exposing that content to AI clients.

Non-negotiables: clean code, DRY, KISS, small single-purpose units, strict
TypeScript, no `@ts-nocheck`, no side effects inside React state updaters.

The user asked not to be asked questions. Every gap below is resolved with a
stated decision (§10).

## 2. QA findings on the template (localhost:3000, 2026-09-29)

| # | Finding | Root cause | Resolution in the rewrite |
|---|---|---|---|
| Q1 | Scrolling the mouse wheel over the open role picker scrolls the page (`scrollY` 0→100); the role does not change and the picker closes as the page moves away. | React's `onWheel` is registered **passive**, so `preventDefault()` is ignored. The listener also only covers the 3-row window, not the hint or the drum. | Native `wheel` listener with `{ passive: false }` on the whole picker wrapper while it is open, plus `overscroll-behavior: contain`. Page scroll is never touched while the pointer is over the open picker. |
| Q2 | Console: "Cannot update a component while rendering a different component" on every role change. | `setRole` calls `history.replaceState` and the imperative hooks **inside** a `setState` updater. | Pure reducer for role state; persistence (hash, `localStorage`) happens in an effect. |
| Q3 | After a theme toggle (and after the blowout) the headline drum shows "Software engineer" while the state, bio and `aria-label` say "AI engineer". | The WebGL drum's repaint closure captures the initial role. | Drum is rebuilt as a CSS 3D prism rendered from React state; there is nothing to repaint. |
| Q4 | Reloading with a saved role renders the default role on the server and then visibly morphs to the saved one. | Stored role is applied after paint, via the animated path. | Stored/hash role is applied in `useLayoutEffect` with the **non-animated** path, before first paint. |
| Q5 | The 3D figure takes several seconds to reassemble after a role change, and still looks scattered at 2s. | three.js line morph. | Replaced by the Spline scene (§6.8); no per-role geometry in this phase. |
| Q6 | Mid theme-fade, paper and ink cross the same grey, so bold text briefly loses contrast. | A simultaneous 380ms colour cross-fade. | Behaviour kept as-is (the user asked to keep the switch exactly as it is). Recorded here so it isn't mistaken for a regression. |

What works and must be preserved: word morph (only changed words animate),
rocker frame animation + synthesized click, the 10-click blowout (flicker from
click 6, bulb, vignette, physics fall, shards, smoke, recovery), curious mode
(rails, width bracket, section guides, 64px gap markers, Caveat notes, per-role
formula notes), role keyboard shortcuts `1..n`, hash deep links.

## 3. Architecture

```
apps/payload  (port 3001)  Payload 3 + SQLite, admin + REST + MCP. No frontend.
   │  REST  GET /api/globals/*, /api/<collection>?depth=1
   │  afterChange hooks ──POST /api/revalidate (secret)──┐
   ▼                                                      │
apps/web      (port 3000)  Next 16 App Router             │
   app/page.tsx (server)  → getPortfolio() → <Portfolio>  ◄┘ revalidateTag('cms')
packages/cms-types         payload-types.ts generated by apps/payload, imported by web
```

- The web reads the CMS over **REST from server components only**, using
  `fetch(..., { next: { tags: ['cms'], revalidate: 300 } })`. There is no
  client-side CMS fetching.
- One mapping layer (`lib/cms/mappers.ts`) turns Payload documents into small
  view models. Components never see Payload types.
- The rich-text bio is serialized to the morph's HTML dialect on the server
  (`lib/cms/bio-html.ts`). Its output is escaped, and links are restricted to
  `http(s):` and `mailto:`.
- `apps/payload`'s package is renamed `cms`, so the workspace name no longer
  shadows the `payload` npm dependency.

## 4. CMS content model (`apps/payload`)

Removed from the website template: Pages, Posts, Categories, Header, Footer,
form-builder, search, redirects, nested-docs, seo and live-preview; the
`(frontend)` route group; seed endpoint and blocks, heros, and unused
components/utilities. Kept: Users (auth), Media (uploads), the Lexical editor
and the MCP plugin.

### Collections

| Slug | Admin label | Fields |
|---|---|---|
| `disciplines` | Disciplines (roles) | `title` ("Software engineer"), `slug` (unique, e.g. `se`), `order` (number), `level` ("LV 9 · backend", shown in the picker), `bio` (Lexical: paragraphs, bold, and inline blocks `chipLink` + `curiousToggle`), `figureCaption`, `curiousNotes[]` { `side`: left/right, `text`, `formula`? } |
| `experiences` | Professional background | `company`, `chip` (≤3 chars), `url`?, `title`, `startYear`, `endYear`? (empty = present), `disciplines` (hasMany relation), `order` |
| `projects` | Portfolio | `name`, `chip`, `url`?, `summary`, `disciplines` (hasMany), `order` |
| `content` | Content & community | `title`, `kind` (article / talk / podcast / open-source / community), `venue`?, `url`, `date`, `disciplines` (hasMany; empty = every role), `order` |
| `media` | Media | upload (alt required) |
| `users` | Users | auth |

The bio's inline blocks are `chipLink` { `label`, `chip`, `url`? } and
`curiousToggle` { `word`, default "curious" }. The `bio` field's admin
description states the authoring rule that makes the morph readable: keep the
same sentence skeleton across disciplines and change only the vocabulary.

### Globals

| Slug | Fields |
|---|---|
| `profile` | `name`, `headlineTail` ("and builder."), `email`, `location`?, `avatar`? (media) |
| `contact` | `links[]` { `label`, `chip`, `url` }: the row under the figure (message, LinkedIn, GitHub) |
| `navigation` | `items[]` { `label`, `href`, `newTab` }: rendered as a quiet footer nav; section anchors (`#work`, `#projects`, `#content`) are valid hrefs |
| `site-settings` | `seo` { `title`, `description`, `ogImage`? }, `defaultDiscipline` (relation), `figure` { `splineSceneUrl`? }, `sectionLabels` { `work`, `projects`, `content` }, `pickerHint`, `pageNotes` { `headline`, `columnWidth` (supports `{w}`), `wallSwitch`, `sectionGap`, `chips`, `role` } |

Access: public `read` on all portfolio collections and globals; writes need an
authenticated user. `afterChange`/`afterDelete` hooks on every portfolio
collection and global call the web revalidate endpoint. Failures there are
logged and never block the save.

### Seed

`src/seed/` holds the content as typed data plus an idempotent runner
(`bun run seed`) that upserts disciplines by `slug`, collections by natural key,
and globals by update. The seed data is the content in the template. It is the
only real content available: Autodoc, the work history, projects, and the three
parallel bios. The user edits it afterwards in the admin or over MCP.

The SQLite file is backed up to `payload.db.bak` and recreated, because the
schema is replaced wholesale.

### MCP plugin

`mcpPlugin` exposes `disciplines`, `experiences`, `projects` and `content` with
find/create/update/delete, `media` with find only, and all four globals with
find/update. Each has a description written for model tool-selection.
`overrideResponse` strips nothing sensitive, because these are public-read
documents. API keys are created by the user in **Admin → MCP → API Keys**.
`apps/payload/README.md` documents the Claude Code connection:

```bash
claude mcp add --transport http payload http://127.0.0.1:3001/api/mcp --header "Authorization: Bearer <MCP_API_KEY>"
```

## 5. Web app structure (`apps/web`)

Feature folders; each unit has one job and a small public surface.

```
app/
  layout.tsx            fonts (Inter variable, Caveat), <ThemeScript/>, metadata from site-settings
  page.tsx              server: getPortfolio() → <Portfolio data={…}/>
  api/revalidate/route.ts   POST, secret-checked, revalidateTag('cms')
  error.tsx, globals.css  (imports styles/tokens.css + styles/base.css)
lib/
  cms/     client.ts (typed fetch), queries.ts (getPortfolio), mappers.ts, filter.ts (client-safe
           filterByDiscipline, so the lists don't pull in the mappers), bio-html.ts, types.ts (view models)
  audio/   context.ts (lazy shared AudioContext), click.ts, bulb.ts, thud.ts, poof.ts
  dom/     page-rect.ts, reduced-motion.ts (usePrefersReducedMotion)
  format/  period.ts ("2021–23", "2023–")
features/
  role/      RoleProvider (reducer + persistence effect), useRole, role-cycle.ts (pure index math),
             RoleDrum (CSS 3D prism), RolePicker (wheel/drag/keys), useWheelStep
  bio/       Bio (ref + innerHTML), morph/{tokenize,lcs,split-strong,plan}.ts (pure), useWordMorph
  theme/     ThemeProvider, ThemeScript, theme-storage.ts, transition.ts, WallSwitch/{WallSwitch,useRocker,rocker-atlas.ts}
  blowout/   useBlowout (click window + flicker level), physics.ts (pure), sequence.ts (DOM choreography), Blowout.module.css
  curious/   CuriousProvider, CuriousToggle (delegated inside the bio), CuriousOverlay, guides.ts (pure measure→guides), useSelfHealingLayout
  figure/    Figure (caption + lazy SplineScene), SplineScene (client, next/dynamic ssr:false;
             `@splinetool/runtime` directly with the WebGL renderer, see §6.8)
  sections/  EntryList (generic chip/title/meta/aside row), WorkSection, ProjectsSection, ContentSection, ContactLinks, FooterNav
shared/ui/   Chip, ChipLink, Section, motion.module.css (the shared `enter` entrance, composed by lists and caption)
styles/      tokens.css (light/dark palette, 3-state theme selectors, metrics), base.css
```

Styling uses CSS Modules per component, plus global tokens. The measured values
(600px column, 15/24 body, 28px h1 at 620/430, 64px section gap, 16px chips,
2px underline at 2.7px offset, the three radial glows) are taken from the
template's `globals.css` and `CONTEXT.md §3` and live in `tokens.css` as custom
properties. Components use the tokens and never hard-code these values.

### State and data flow

- `RoleProvider` holds `{ role, animate }` in a reducer. Actions are
  `select(slug)`, `step(±1)` and `hydrate(slug)`; `hydrate` doesn't animate.
  One effect writes `localStorage` and the hash. Everything that depends on the
  role (drum, bio, lists, caption, curious notes) reads context. There is no
  event bus.
- The `ThemeProvider` owns `light | dark | system`. `ThemeScript` sets
  `data-theme` before paint. Every toggle stamps `data-theme-transition` for
  380ms. A `MutationObserver` keeps the rocker in sync when the theme changes
  from outside (system or another tab).
- The `CuriousProvider` owns the on/off state, persisted to `localStorage`.
  The overlay recomputes guides when the role changes, on resize, on a
  `ResizeObserver` over `main`, and on `document.fonts.ready`.

## 6. Behaviour specs (parity with the reference, plus fixes)

1. **Role drum.** An N-sided CSS 3D prism (`rotateX`, face angle `360/N`,
   `backface-visibility: hidden`). It rolls to the current role at the
   reference's easing; under reduced motion it jumps. It works for any number
   of disciplines ≥ 1. The drum is a `<button aria-haspopup="listbox">` whose
   label names the current role.
2. **Role picker (wheel).** Opens on hover or focus and shows 3 rows of 42px
   with the current role on the raised `.sel` plate and a masked window. The
   list holds three copies of the order for infinite looping, renormalised after
   each step (pure `role-cycle.ts`). Input:
   - wheel: accumulate `deltaY`, step at |acc| ≥ 26, 170ms cooldown
     (non-passive, whole wrapper, no page scroll — Q1)
   - pointer drag, for touch
   - arrow keys; Escape closes
   - click a row to jump there
   - close after a 160ms soft-hide on leave, or on a click outside
   Each step commits the role immediately.
3. **Word morph.** Pure pipeline: `splitStrong` splits multi-word `<strong>`
   into single words. `tokenize` keeps chip links and the curious toggle
   atomic and records the whitespace after each token. `lcs` computes the keep
   sets. `plan` returns the out/in spans. `useWordMorph` runs the two phases:
   `.out` → swap after 240ms → `.in`, cleared on the second rAF with a
   `(i % 14) × 9ms` stagger. A new morph flushes a pending one. Under reduced
   motion the swap is instant.
4. **Wall switch.** Behaviour is the reference's, unchanged:
   - 17-frame atlas (5 columns, 212×280), validated, with `<img>` fallback
   - smoothstep flip of 200ms per frame; a click mid-flip snaps to the end first;
     clicks under 300ms apart flip in 115ms
   - LCG-seeded noise click through a bandpass (1450Hz to light, 1050Hz to dark)
   - 380ms theme transition joined by every coloured element
   - `position: fixed` top-right below 900px
5. **Blowout.** Same constants as `CONTEXT.md §5`:
   - 4s window, flicker levels 1–4 from click 6, sequence on click 10
   - bulb MP3 decoded on the 2nd fast click
   - flash and vignette; the cloned switch falls under physics with g=2700,
     wall bounce 0.5, floor restitution 0.34 with a speed-scaled thud,
     friction 0.82, settling to the nearest right angle
   - 16 shards; smoke puff at 3300ms; previous theme restored under the veil
   - clicks ignored while the sequence runs; reduced-motion variant
   Physics is a pure step function with unit tests. DOM choreography is a
   separate module.
6. **Curious mode.** The toggle is a `role="switch"` pill inside the bio
   (inline block from the CMS). It is delegated so it survives the morph's
   `innerHTML` swaps, and `aria-checked` is re-synced after each morph. The
   overlay draws:
   - rails, the live-measured width bracket, and section guides (bio / figure /
     work / projects / content)
   - 64px gap markers
   - page notes from `site-settings.pageNotes`
   - per-role formula notes from `disciplines.curiousNotes`, placed beside the
     figure
   Notes are hidden below 1040px. Guides stagger in 35ms apart. Guide geometry
   is computed by a pure function from measured rects.
7. **Lists.** Work, Projects and Content use one generic `EntryList`; each row
   is chip link + title + meta + right-aligned aside. Each list is filtered by
   the current discipline. When the role changes, the lists cross-fade (opacity
   and blur, ~240ms), so all text on the page moves with the role. The Content
   section renders only when it has entries.
8. **Figure (Spline).** The three.js plate is replaced by a Spline scene,
   driven through `@splinetool/runtime`'s `Application` directly with
   `renderer: 'webgl'`, not through `@splinetool/react-spline`: the wrapper
   can't select the renderer (on the auto-selected WebGPU pipeline this scene
   logs validation errors and drops draws) and has no error callback (it
   rethrows a failed load during render), so the figure couldn't collapse to
   its caption. The scene URL comes from
   `site-settings.figure.splineSceneUrl`; `public/spline/scene.splinecode` is
   the default when that field is empty. The scene is lazy-mounted when near
   the viewport and loaded client-only. The frame is 3:2 at the column's
   width (600×400 on desktop, scaling down on mobile), not the template's
   216px strip: at 216px (and even 16:9) the scene's framing crops the lamp
   and the plant. The frame holds its size while the scene loads, so there is
   no layout shift. The scene's camera is orthographic, so it frames as many
   scene units as the canvas has CSS px: the scene renders into a fixed stage
   (600×400 ÷ 0.7, pulled back so the whole desk has a margin) scaled into
   the box, which keeps the same framing at every width. `app.setZoom` can't
   do this: on an orthographic camera it's an absolute zoom clamped to the
   scene's limits. If the scene is missing or fails to load, the figure
   collapses to its caption and the page stays fully usable. The caption is
   per-role. Per-role scene actions are out of scope for this phase.
   *GPU cost (accepted, 2026-09-30):* the stage always renders about
   857×571 CSS px × `devicePixelRatio` (≈ 1714×1142 device px on a 2× screen),
   even when it is scaled down into a narrow mobile box. The runtime has no
   pixel-ratio option to cap that, and the fixed stage is what keeps the
   framing, so the cost is accepted rather than worked around.
9. **Accessibility.**
   - `role="status"` announces role changes
   - visible focus rings everywhere
   - keyboard access to drum, picker, switch and toggle
   - reduced motion disables the morph animation, physics, flicker and drum roll
   - with JavaScript off, the letter, lists and the switch's `<img>` state still
     render

## 7. Error handling

- CMS unreachable while building or revalidating: `getPortfolio` throws.
  During ISR, Next keeps serving the last good page; on a cold build the build
  fails loudly. `error.tsx` renders a minimal letter-styled message.
- Missing optional content (no URL, no end year, no content entries, no scene)
  is handled in the mappers. Components receive complete view models and have
  no null checks.
- The revalidate endpoint returns 401 on a bad secret and 200 `{ revalidated: true }`
  on success.
- WebGL/Spline failure is isolated to the figure. Audio failures (autoplay
  policy, decode errors) are swallowed inside `lib/audio`, so the switch still
  toggles.

## 8. Testing

- **Unit (Vitest, apps/web):** tokenize, lcs, splitStrong, plan, role-cycle,
  physics step, rocker frame math, period format, bio-html serializer
  (including escaping and URL filtering), mappers. Written test-first.
- **Unit (Vitest, apps/payload):** seed data integrity, meaning every
  discipline has 5 bio paragraphs and every relation slug exists.
- **E2E (Playwright, apps/web, run against the CMS on 3001):**
  - the wheel over the open picker changes the role and leaves `scrollY`
    unchanged (Q1)
  - no console errors on a role change (Q2)
  - the drum label matches the role after a theme toggle (Q3)
  - a saved role renders without a morph on reload (Q4)
  - the theme persists across reload with no FOUC
  - curious mode draws guides and the notes change with the role
  - the page reads with JavaScript disabled
- `check-types`, `lint` and `build` pass for web and cms.

## 9. Out of scope

- Per-role Spline scene states or actions (next phase).
- A contact form, a blog, or multiple pages.
- Localisation.
- Deployment.

## 10. Decisions taken without asking

1. **Content.** The seed uses the template's copy. It is the only content
   available, and the bio already names Autodoc. It is editable in the admin or
   over MCP.
2. **Styling.** CSS Modules plus global tokens, not Tailwind, to keep the
   measured values exact and the markup quiet.
3. **Drum.** CSS 3D instead of WebGL, which removes three.js entirely now that
   the figure is Spline (Q3, KISS).
4. **CMS access.** REST plus shared generated types, not Payload's Local API in
   web, so the two apps stay decoupled.
5. **Ports.** Web on 3000, CMS on 3001, matching what is running today.
6. **Spline asset.** `docs/assets/interactive_workspace.spline` is an editor
   file. Implementation first tries loading it with `@splinetool/runtime`. If it
   doesn't load, the export URL goes in site-settings (Spline → Export → Code →
   copy the `.splinecode` URL), and the figure falls back to caption-only until
   that is set.
7. **Navigation global.** It drives a minimal footer nav, because the design has
   no header.
8. **Package name.** `apps/payload` becomes the `cms` package.
9. **Role persistence.** Kept (localStorage + hash), applied before paint (Q4).

## 11. Addendum (2026-09-30): Blog, CMS only

The user asked for the Payload blog feature to be ready, following Payload's "How to build a website, blog or portfolio with Next.js" guide. The blog is not linked to the portfolio yet.

The scope covers:
- `posts`, with:
  - drafts and autosave (debounced: it saves after a ~2s pause in typing, `interval: 2000`; a "Save draft" button saves right away)
  - a slug from Payload's core `slugField`, kept in sync with the title (formatted by our `formatSlug`) until the editor unlocks it
  - draft preview at `/blog/<slug>` and live preview at `/blog/preview/<id>`, keyed by id so the iframe URL stays stable while the slug follows the title
  - scheduled publish via the jobs queue
  - published-only public reads
  - a Lexical editor with code, banner and media blocks
  - categories, authors (names only, never emails), related posts and `publishedAt`
- nested `categories`
- plugins: SEO (posts), search (posts) and redirects (posts)

The database changes must be additive only, and the database is backed up first. No content is written. MCP is not extended; the user paused that work. See plan Task 27.
